# CRM 交互复检与优化（2026-09-07）

## 范围与业务理解

本轮从已有未提交改动继续检查，没有重置工作区。已有 `CRM界面与交互检查.md` 中的发布记录属于此前工作，本报告记录后续复检及用户提供服务器信息后的部署验证。

实际业务以当前代码、角色权限与 API 为准：调度员录入及首次分配；邀约师/销售领取、联系客户、创建到访预约；主管负责分配、排班、转交和异常处理；谈单师承接到访后的谈单；管理员维护人员、渠道和业务规则。资料、跟进记录与成交/退款纠错需要保留业务上下文。

检查覆盖登录、工作台、详情、新建、跟进、预约创建、日程、公海、统计、修改密码、系统设置四栏目和 404。保留现有 Vue/Vant、设计 Token、页面结构、权限与后端状态机；部署仅更新前端静态资源，未重启后端服务；数据库、通知、CMS 和其他站点保持原状。

## 本轮确认并修复的问题

| 场景 | 原有问题 | 优化结果 |
| --- | --- | --- |
| 退出账号 | 仅调用退出接口，不检查失败，也不离开客户工作台 | 失败提示可重试；成功进入登录页；实际 API 验证 Cookie 清除、旧会话不能获取用户资料 |
| 公海分页 | 第二页失败时隐藏第一页面板，且没有明确错误入口 | 保留已加载客户与数量，提供“重试加载更多”，继续失败页且不重复记录 |
| 公海搜索与认领 | 正在加载时搜索被忽略；未提交搜索词可能混入下一页；取消认领会形成未处理异常 | 仅采用最新搜索响应，分页沿用已提交条件；认领防重复，取消静默、失败明确反馈 |
| 新建/跟进/预约表单 | 误点导航或刷新丢失输入；提交过程中可离开 | 有修改时提示继续填写或放弃；刷新使用浏览器原生保护；提交中阻止站内离开；提交成功正常跳转，不额外确认 |
| 新建联系方式 | 联系方式缺失提示可能出现在手机屏幕之外 | 电话/微信至少一项的校验靠近字段，并自动滚到错误处；提交失败聚焦错误说明 |
| 谈单师新建 | 邀约师加载失败要求刷新整页，已经填写的客户信息会丢失 | 原地重试人员列表并保留所有输入 |
| 跟进和预约返回 | 直接打开深链接时盲目 `back()`，可能离开 CRM 或回错页面 | 缺少对应历史记录时返回当前线索；跟进成功后保留工作台筛选返回地址 |
| 统计切换日期 | 旧响应覆盖新日期数据；加载中先显示零值；取消日历留下“自定义”标签 | 仅应用最新请求；明确显示加载/失败，保留标题与筛选操作；确认日期才切换范围 |
| 日程切换 | 旧日期预约/可用时间响应可能覆盖当前日期；清空日期导致无效日期计算 | 对列表、可用时间与范围读取分别防错序；空日期回到今天 |
| 手机预约排班 | 默认周视图先显示周一空白卡片，今天的预约可能在屏幕外 | 手机首次打开默认日视图，桌面保留周视图，用户仍可切换 |
| 批量分配 | 调度员能选择线索但人员列表不加载；全选谈单线索不加载谈单师；筛选后仍残留旧勾选数量 | 按角色与业务阶段加载合法人员；重新筛选清空勾选，避免对错误对象操作 |
| 平板新建线索 | 桌面侧栏与预览栏挤占表单，输入框只剩几十像素、第五颗星被裁切 | 768–1199px 将预览移到表单下方，保留两列表单；星级允许换行并验证可完整点击 |
| 菜单与阅读 | 手机“更多”缺少键盘焦点管理；账户菜单路由跳转后残留；表单占位提示过浅 | 接入现有焦点管理与 Escape 返回；导航后收起菜单；占位文字使用已有辅助文字 Token |
| 生产环境加载 | Vite 8 的 data: 探测模块被 CSP 拦截，现代 Chrome 错误加载旧版代码；图标字体额外请求被拦截的外部地址 | 探测及启动脚本作为本站资源发布，保留兼容性探测和旧版回退；沿用 Vant 内嵌 WOFF2，移除外部备用字体；不放宽服务器安全策略 |
