# CRM AI 分析验收、发布与回滚

本文件定义验收执行方式。未执行的项目必须标为“未验证”，不能根据功能存在、静态阅读或可控模型测试改写为通过。

**整体验收仍未完成。** 最新候选、真实模型失败及发布状态见项目根目录 `docs/CRM-Agent-验收与发布记录-20261013.md`；下面的用例数量和执行计划不是通过记录。

## 验收材料

- `Agent-Evaluation-Fixture.json`：七条小业务数据及独立数字；另有 10001 条线索/50005 条跟进压力数据生成口径。全部为隔离数据，禁止导入线上业务库。
- `Agent-Evaluation-Cases.json`：44 个验收用例，前 30 条为自由业务查询；不是限制用户的问题白名单。数字以独立 SQL 为准。44 项包含真实业务问答、需要独立压力数据的问题，以及预算、授权、导出、界面和性能等场景，不等于给模型连续发送 44 个问题。
- 每次执行保存：代码版本、SQLite 内嵌版本、前端资源哈希、配置模型及供应商返回的模型标识、公共规则版本、数据时点、每条问题与回答、真实结果引用、供应商调用和用量、实际/未知费用、耗时及判定。未返回的真实上游版本标为未知，兼容接口返回的型号标识不视为独立认证。
- 真实模型关键问题重复三次；数字、脱敏、授权和只读权限要求三次全部通过。自然语言结论必须由人工核对证据是否支持，不以另一个模型评分代替。

## 用例范围与真实调用编排

| 用例 | 执行方式与范围 | 数量说明 |
|---|---|---|
| A01–A30、A37、A41–A43 | gold 真实模型默认选择范围；A37 覆盖说明，A41–A43 去重及多轮纠正；每项均须独立语义审查 | 34 项；推荐显式 `--repeat-policy`，按当前清单为 90 次完整用例重复、102 轮分析 |
| A35、A36 | `--dataset stress-v1`，独立 10001 条线索/50005 条跟进的真实模型压力及分页问题 | 2 项，各三次，共 6 轮；不能套用 Go 性能夹具 50001 条跟进的预期 |
| A31、A32、A33、A34、A38、A39、A40 | 专项确定性/集成/浏览器/性能场景，不能作为自由问题直接交给默认 runner | 7 项；下文说明确定性证据与仍需真实环境验证的边界 |
| A44 | 显式 `--cases A44 --repeat-policy`，同一真实会话依次执行全部条件更正及追问 | 1 项，完整执行一次为 12 轮；最后一轮前核对真实保存的 22 条消息；不预置虚构历史 |

“用例重复次数”与“分析轮次”不同：A26 每次有三轮，A27/A43 每次有两轮；每轮分析还可能调用模型多次，仍受每轮八次上限。34 项加上其重复不能写成“已通过 102 个不同问题”。

推荐在离线计划和真实执行中都显式使用 `--repeat-policy`：

```sh
# 只打印编排，不读取访问凭证、不发 HTTP、不产生费用。
python3 scripts/agent_live_evaluate.py --print-plan --repeat-policy
python3 scripts/agent_live_evaluate.py --print-plan --cases A44 --repeat-policy
```

当前 runner 保留兼容默认：**真实执行省略 `--repeat-policy` 和 `--repeat` 时，每项执行三次**。因此 gold 默认 34 项会是 102 次用例重复、114 轮分析；显式选择 A44 却省略重复策略会是 36 轮。`--print-plan` 在未传 `--repeat` 时自动采用清单策略，所以不能省略实际执行的 `--repeat-policy` 后仍按打印出的 102/12 轮理解费用。

离线计划中的费用是每轮三元上限的累加，不是实际消费，也不是突破三百元月预算的授权。真实执行还需要显式 `--allow-paid-requests`、私有 `--fixture-access`、项目外输出目录，以及适当的 `--max-spend-yuan` 批次限额；批次限额、每轮/每月预算、未知用量预留全部继续生效。不能为了跑完整编排自动增加预算或清空旧预留。实际运行的候选、配置、规则与用例清单必须固定并保存散列。

专项场景的证据边界：

- **A31 导出不变性**：`TestHistoricalHTTPExportsRemainImmutableAfterBusinessChangesAndCacheExpiry` 使用真实隔离 SQLite、BuildSnapshot/Query/saveResult、已完成回答及 HTTP 导出；实际更新来源/金额、增加线索，新快照确认变化，再核对历史 API、Excel 全量数据与 HTML 固定图表。旧导出过期并物理删除后重新生成仍一致。该确定性测试零云调用；真实浏览器的图表/导出展示另行验收。
- **A32/A33 预算与跨月**：使用 SQLite 并发预留、重复结算、未知用量与跨月确定性测试，不为构造这些边界专门重复真实付费。真实评测费用仍按其实际 reservation 独立对账。
- **A34 授权**：确定性账号/HTTP 测试覆盖其他管理员私有资源、禁用及降权；真实浏览器的第二隔离账号权限检查是补充，不能混称为全部管理员组合已经实测。
- **A38 恢复**：可控协议/实际子进程测试证明幂等、取消及重启行为；真实模型浏览器的断流/刷新/停止和独立同库进程崩溃恢复仍分别执行，操作见 `Agent-Live-Browser.md`。
- **A39 界面**：既有浏览器回归覆盖尺寸、输入、错误恢复等可控行为；真实模型内容与多端展示仍须实际浏览器验证。未执行的软键盘、读屏或设备交互不能据桌面构建宣称通过。
- **A40 性能**：隔离业务 HTTP 与两项可控 Agent 并发用于可重复计时，不产生云费用；最终冻结版本必须在目标两核资源、无 profile/trace 干扰的同负载下满足原 P95/锁错误标准。

A44 另有确定性条件管理及恢复回归，但这些不能替代十二轮真实对话。`completed` 只说明运行结束，正确性必须逐轮检查独立 SQL、条件来源、最终事实及额外主张。

## 本模块专项自动测试

在 `apps/kxone` 执行：

```sh
go test ./internal/agent -count=1
go test -race ./internal/agent -count=1
```

预算测试使用真实 SQLite WAL 多连接：40 路并发预留只允许剩余额度内调用，20 路重复结算只计一次；验证跨月、未知用量、超预留、单轮累计和取消上下文。

导出测试真实打开生成的 `.xlsx`，检查结果、口径页和精度；确认 `=HYPERLINK`、`+cmd` 与制表符前缀文本不生成公式。HTML 验证恶意脚本/HTML被转义、图表绑定真实数字、截断和缺失结果错误不会静默隐藏。

模型与设置安全测试使用本地 HTTP 模型协议及真实 SQLite：公网 HTTPS、私网/URL 凭证拒绝、确定性 DNS 重绑定、供应商错误不回显密钥、token 输出截断仍保留 usage、费率核算与界限；验证管理员网页密文保存、留空保留、明确删除、冲突不写入、新模型确认费率、公共规则追加版本、付费连通测试、两位其他管理员的私有会话/SSE/结果/导出拒绝、缺失账号依赖拒绝、禁用/降权/停止长流、配置变化取消旧调用，以及幂等请求和事件游标重连不重复收费。

还需整体执行 Go、前端单测、构建、资源预算和既有 CRM 回归。真实浏览器验证 SSE、中文输入法、软键盘、会话返回、导出及错误恢复，使用 320/375/768/1440 宽度。可控模型只用于确定协议/错误，不满足真实云模型 API 验收。

## 真实 API 的验证边界

使用管理员明确选择并保存的专用模型接入和隔离客户数据；原计划默认百炼，后续产品要求允许更换兼容接口。密钥可由环境初始注入或由管理员通过网页系统设置保存；原 Key 不回显、不写入证据，日志仅记录是否配置。网页配置验收包括管理员专属写入、留空保留、显式清除、版本冲突、数据库密文与不发送业务数据的付费连通测试。实际出站前用 fixture 的 `forbidden_provider_payload_fragments` 检查原姓名、手机号变体、微信、座机和账号密码哨兵不存在；不合格请求直接阻止发送。证据默认只保存请求散列和核验状态。自由文本非登记姓名与家长信息需额外构造样本核验。

`TestAgentLiveAcceptance` 仅在明确环境开关下启动，客户、账号、会话及结果使用临时 SQLite；线上连接仅允许读取模型配置和配置管理员的必要身份字段，以及在独立受限连接中写入共同费用账本。每次调用前原子预留，未知用量保留；配置版本或管理员状态变化立即阻止后续出站。`scripts/agent_live_evaluate.py` 按上文范围及明确重复策略采集真实评测，使用活动互斥锁和幂等请求恢复，仍需独立审查数字与语义，不自动把 completed 认作验收通过。真实浏览器与独立进程恢复执行见 `Agent-Live-Browser.md`。

供应商没有返回可靠 usage 的请求标为未知，并在预算保留预留；不能填零元。真实模型未配置或不可访问时，记录具体阻塞项，保留本地交付；不能上线开启新分析，也不能把可控模型当成真实验收。

## 数据完整性与业务性能

对独立大数据集确认全量数：10001 条线索、50005 条跟进、5001 个 A 来源、5000 个 B 来源、净成交额 5001 元。数据查询总数不受明细展示限额影响，多表连接不能把金额乘以五。

同数据同负载分别采集无分析基线和两项分析并发：新增、领取、跟进的样本量/P50/P95、错误数及 SQLite 锁错误。验收标准是无分析造成的业务写锁失败，业务接口 P95 退化不超过 20%。快照构建时间、内存和临时磁盘峰值另行记录；模型长耗时期间不持有业务库事务。

## 发布与故障处理

1. 发布前保存未提交改动清单和可恢复快照；基于已有安全加固版本进行独立构建。执行 SQLite 在线备份、只增字段/表迁移演练和回滚演练，核对 SQL/checksum 顺序。
2. 数据/模型接入基础版本保持 Agent 默认关闭。真实模型、浏览器及关键业务验收通过后再开启新分析并替换旧统计入口。
3. 发布后核验 systemd 运行版本、静态资源哈希、健康、迁移、数据库完整性、SSE 心跳和功能开关。生产仅做只读检查，不创建测试客户或付费测试请求。
4. 故障优先关闭新分析，历史会话、结果及已有导出继续可读；保留未知费用和中断状态。预约、自动回收、通知开关保持既定值。
5. 回滚应用及资源到包含鉴权修复和本轮 SQLite 驱动更新的安全基线。保留新增分析表和业务数据，不恢复整库覆盖发布期间新增记录。

交付时附问题对照、实际执行结果、未验证项、数据库迁移记录、用量与费用、发布版本及回滚路径。只有真实模型与实际浏览器通过，才能标记对话式 Agent 完成。
