# KXOne 快速启动指南

## 环境要求

- Go 1.25+
- Node.js 20.19+（前端构建与测试）
- MySQL 8.0+ 或 SQLite（开发环境）
- Redis 6.0+

## 1. 安装 Go（macOS）

```bash
brew install go
```

验证安装：
```bash
go version  # 应显示 go1.25 或更高版本
```

## 2. 配置环境变量

复制配置示例并修改：
```bash
cp .env.example .env
```

编辑 `.env`，关键配置：

**开发环境（SQLite）**：
```bash
DB_DRIVER=sqlite
DB_NAME=kxone.db

REDIS_HOST=localhost
REDIS_PORT=6379

WECOM_CORP_ID=your_corp_id
WECOM_AGENT_ID=1000001
WECOM_SECRET=your_secret
WECOM_TOKEN=your_token
WECOM_ENCODING_AES_KEY=your_encoding_aes_key

FIELD_ENCRYPTION_KEY=
MOBILE_HASH_KEY=
JWT_SECRET=replace_with_long_random_secret
AD_LEAD_DEFAULT_MANAGER_USERID=manager_001
```

**生产环境（当前 SQLite）**：
```bash
DB_DRIVER=sqlite
DB_NAME=/opt/kxone/data/kxone.db
SERVER_PUBLIC_BASE_URL=https://your-domain.com
FIELD_ENCRYPTION_KEY=base64:your_32_byte_field_encryption_key
MOBILE_HASH_KEY=base64:your_32_byte_mobile_hash_key
JWT_SECRET=replace_with_long_random_secret
AD_LEAD_DEFAULT_MANAGER_USERID=真实主管的企业微信 UserID
```

`AD_LEAD_DEFAULT_MANAGER_USERID` 是广告线索和官网公开表单的默认派发主管。生产环境缺失时 KXOne 会拒绝启动，避免官网显示提交成功但线索无法进入待派发流程。公开表单不能通过请求参数覆盖该主管。CMS 管理端已从本仓库移除，`CMS_ENABLED=true` 会被生产检查拒绝。

官网表单默认提交到同源 `/api/public/leads/form`。生产 Nginx 应代理 `/api/` 到 KXOne。如果 CRM 与官网使用不同域名，把官网 Origin 加入 `CORS_ALLOWED_ORIGINS`：

```bash
SERVER_PUBLIC_BASE_URL=https://CRM正式域名
CORS_ALLOWED_ORIGINS=https://官网正式域名
AD_LEAD_DEFAULT_MANAGER_USERID=真实主管的企业微信 UserID
```


## 3. 安装依赖

```bash
go mod download
```

## 4. 启动 Redis（开发环境）

**macOS**：
```bash
brew install redis
brew services start redis
```

**验证 Redis**：
```bash
redis-cli ping  # 应返回 PONG
```

## 5. 初始化数据库

### SQLite（开发环境自动创建）
开发环境启动服务时会先通过 GORM AutoMigrate 创建/补齐 `kxone.db` 文件和表结构，再执行 `migrations/*.sql` 记录版本化变更。

### MySQL（需要手动创建数据库）
```bash
mysql -u root -p
```

```sql
CREATE DATABASE kxone CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
EXIT;
```

生产环境默认关闭 GORM AutoMigrate，表结构由 `migrations/*.sql` 创建和演进；后续 schema 变更请新增版本化 SQL 迁移。

## 6. 启动服务

```bash
make dev
```

或直接运行：
```bash
go run cmd/server/main.go
```

服务启动后，访问：
- 健康检查：http://localhost:8080/health
- API 基础路径：http://localhost:8080/api

## 7. 配置企业微信

### 7.1 创建自建应用

1. 进入企业微信管理后台
2. 应用管理 → 自建应用 → 创建应用
3. 记录以下参数：
   - CorpID
   - AgentID
   - Secret

### 7.2 配置回调地址

在应用管理中配置：
- 回调 URL：`https://your-domain.com/api/wecom/callback`
- Token：随机生成（与 `.env` 中 `WECOM_TOKEN` 对应）
- EncodingAESKey：随机生成（与 `.env` 中 `WECOM_ENCODING_AES_KEY` 对应）

### 7.3 配置可信域名

在应用配置中添加：
- H5 可信域名：`your-domain.com`

### 7.4 设置应用可见范围

添加所有主管和销售到应用可见范围。

## 8. 测试接口

### 健康检查
```bash
curl http://localhost:8080/health
```

### 企业微信回调验证（需要外网访问）
```bash
# 企业微信会发起 GET 请求验证
curl "http://localhost:8080/api/wecom/callback?msg_signature=...&timestamp=...&nonce=...&echostr=..."
```

### OAuth 登录测试
```bash
# 用户从企业微信点击应用后，企业微信会回调：
curl "http://localhost:8080/api/auth/wecom/callback?code=xxx"
```

### 开发环境获取调试 Token
`SERVER_ENV=dev`、`ENABLE_DEV_TOKEN=true` 且配置 `DEV_TOKEN_SECRET` 时，可以使用开发调试接口生成不同角色的 JWT：

```bash
curl -X POST http://localhost:8080/api/auth/dev-token \
  -H "Content-Type: application/json" \
  -d '{"wecom_userid":"manager_001","role":"manager","secret":"change-me-for-local-dev"}'
```

返回结果中的 `access_token` 可用于调用需要认证的接口：

```bash
TOKEN="上一步返回的 access_token"
```

### 创建测试线索并进入派发流程
```bash
curl -X POST http://localhost:8080/api/leads \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "customer_name": "王先生",
    "customer_mobile": "13812345678",
    "city": "上海",
    "product_name": "企业服务套餐 A",
    "source_channel": "百度搜索",
    "lead_level": "high"
  }'
```

该接口会创建 `pending_dispatch` 线索，并异步尝试发送主管待分配企业微信卡片。

### 本地跑通分配、领取、跟进
生成销售 token：

```bash
SALES_TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/dev-token \
  -H "Content-Type: application/json" \
  -d '{"wecom_userid":"sales_001","role":"sales","secret":"change-me-for-local-dev"}' \
  | sed -n 's/.*"access_token":"\([^"]*\)".*/\1/p')
```

主管分配线索：

```bash
curl -X POST http://localhost:8080/api/leads/1/assign \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"sales_userid":"sales_001","remark":"优先联系"}'
```

主管转派线索：

```bash
curl -X POST http://localhost:8080/api/leads/1/reassign \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"sales_userid":"sales_002","remark":"原销售忙碌，转派处理"}'
```

销售领取线索：

```bash
curl -X POST http://localhost:8080/api/leads/1/claim \
  -H "Authorization: Bearer $SALES_TOKEN"
```

销售提交跟进：

```bash
curl -X POST http://localhost:8080/api/leads/1/followups \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $SALES_TOKEN" \
  -d '{
    "followup_result": "connected",
    "intention_level": "high",
    "remark": "客户已接通，下午继续沟通",
    "is_valid": true
  }'
```

查看线索详情：

```bash
curl http://localhost:8080/api/leads/1 \
  -H "Authorization: Bearer $SALES_TOKEN"
```

## 10. 下一步

生产环境应先配置 HTTPS、Nginx 和 systemd。脚本化部署要求远端已有
`$KXONE_REMOTE_DIR/go/bin/go`、Node.js 20.19+、Corepack、`sqlite3` 或带 SQLite 支持的 Python 3，以及
`kxone-server`、`kxone-worker` 两个 systemd 服务：

```bash
export KXONE_SERVER_HOST=your-server.example.com
export KXONE_SERVER_USER=deploy
export KXONE_PUBLIC_URL=https://your-domain.com
export KXONE_SITE_REPO=/absolute/path/to/site-rebuild
# 可选：未使用 SSH Agent 时指定私钥
export KXONE_SSH_KEY=$HOME/.ssh/id_ed25519

./scripts/deploy_kxone.sh
```

部署脚本会在替换文件前对二进制、前端、迁移目录和 SQLite 做一致性备份；
服务启动或健康检查失败时自动恢复上一版本。独立备份使用相同的 SSH 变量：

```bash
./scripts/backup_sqlite.sh
```


## 常见问题

### Q: 企业微信回调验证失败
A: 检查 Token 和 EncodingAESKey 是否配置正确，确保回调 URL 可以被企业微信访问。

### Q: Redis 连接失败
A: 检查 Redis 是否启动、端口和密码是否正确。Redis 承担任务队列、共享限流和企微 Token 缓存，探活失败时 Server/Worker 会拒绝启动，避免以降级但不完整的状态提供服务。

### Q: SQLite vs MySQL 如何选择？
A: 当前 KXOne 生产实际使用 SQLite，现阶段单机规模更看重简单备份、部署和融合成本；当并发写入、跨节点或数据规模明显增长时，再按压测结果迁移 MySQL。代码和迁移仍保留 MySQL 方言兼容。

### Q: JWT Token 过期怎么办？
A: 前端使用 refresh_token 调用 `/api/auth/refresh` 接口刷新 access_token。
