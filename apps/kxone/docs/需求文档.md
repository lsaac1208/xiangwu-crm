# 需求文档：自研 CRM 对接企业微信线索派发与领取流程

> 历史企微方案：OAuth、个人应用卡片派发与回调领取已停用。现行业务、权限、接口和验收以 [CRM现行业务与维护规则](CRM现行业务与维护规则.md) 为准；本文件不作为重新启用旧流程的依据。

## 1. 项目背景

当前公司已自研 CRM 系统，并已将付费推广来源的线索统一接入 CRM 管理。现阶段企业微信仅用于销售群机器人 webhook 消息推送，主要承担“通知”作用，无法完成线索领取、主管派发、销售确认、状态同步、跟进编辑等闭环操作。

本项目拟通过企业微信自建应用能力，将企业微信作为 CRM 的移动端通知与操作入口，实现线索从进入 CRM 到主管派发、销售领取、跟进填写、状态同步的完整闭环。

## 2. 项目目标

### 2.1 核心目标

实现以下业务闭环：

```text
付费推广线索进入 CRM
        ↓
CRM 第一时间推送企业微信卡片给主管
        ↓
主管在企业微信中查看线索并分配销售
        ↓
被分配销售收到企业微信领取卡片
        ↓
销售点击领取
        ↓
CRM 同步领取动作
        ↓
主管卡片、销售卡片同步更新状态
        ↓
销售进入 CRM H5 页面填写跟进记录
```

### 2.2 业务价值

1. 提升付费线索响应速度。
2. 避免线索进入 CRM 后无人及时处理。
3. 由主管统一分配，避免销售乱抢线索。
4. CRM 记录完整操作链路，包括分配人、领取人、领取时间、跟进状态。
5. 企业微信成为销售人员的即时操作入口，减少打开 CRM 后台的成本。
6. 为后续 SLA 统计、销售响应排行、线索转化分析提供数据基础。

## 3. 项目范围

### 3.1 本期包含

1. 企业微信自建应用接入。
2. CRM 新线索推送主管企业微信卡片。
3. 主管在线索卡片中点击“分配线索”。
4. 主管进入 CRM H5 分配页，选择销售人员。
5. CRM 给被分配销售发送企业微信领取卡片。
6. 销售点击“领取”后，CRM 同步更新线索归属。
7. 主管卡片同步更新为“某某销售已领取”。
8. 销售卡片同步更新为“已领取，可填写跟进”。
9. 销售通过企业微信进入 CRM H5 页面填写跟进记录。
10. CRM 记录完整操作日志。
11. 支持超时未分配、超时未领取提醒。

### 3.2 本期不包含

1. 不使用企业微信自带客户联系系统。
2. 不把客户资产迁移到企业微信客户系统。
3. 不通过企业微信直接管理客户微信。
4. 不做会话内容存档。
5. 不做复杂营销自动化。
6. 不做销售自动分配算法，仅预留扩展。
7. 不在企业微信卡片内完成复杂表单编辑，复杂编辑统一进入 CRM H5 页面。

## 4. 角色定义

| 角色       | 说明                  | 权限                       |
| -------- | ------------------- | ------------------------ |
| 主管       | 负责接收新线索、判断线索归属、分配销售 | 查看待分配线索、分配销售、查看领取状态、转派   |
| 销售       | 负责领取主管分配的线索并跟进客户    | 查看被分配线索、领取线索、填写跟进        |
| CRM 管理员  | 维护主管、销售、部门、规则、企微配置  | 配置企业微信应用、配置线索分配规则、查看日志   |
| CRM 系统   | 线索主数据系统             | 创建线索、更新状态、发送企微卡片、接收企微回调  |
| 企业微信自建应用 | 通知与操作入口             | 推送卡片、回调点击事件、打开 CRM H5 页面 |

## 5. 核心业务流程

### 5.1 新线索进入 CRM

当广告、表单、落地页、电话系统、第三方平台等渠道产生新线索后，CRM 统一创建线索记录。

线索初始状态为：

```text
pending_dispatch
待主管分配
```

CRM 根据线索来源、城市、项目、产品线等规则确定应通知的主管。

### 5.2 推送主管卡片

CRM 创建线索后，立即向主管发送企业微信应用卡片。

主管卡片展示内容建议如下：

```text
新付费线索待分配

来源：百度搜索
城市：上海
产品：企业服务套餐 A
客户：王先生
手机号：138****1234
线索等级：高
进入时间：2026-06-16 10:31
```

卡片按钮：

```text
【分配线索】 【查看详情】
```

点击“分配线索”后，打开 CRM H5 分配页。

点击“查看详情”后，打开 CRM H5 线索详情页。

### 5.3 主管分配销售

主管在 CRM H5 分配页中可以看到：

1. 线索基础信息。
2. 来源渠道。
3. 客户所在地。
4. 意向产品。
5. 推荐销售，后续版本支持。
6. 当前可分配销售列表。
7. 销售今日已分配数量，后续版本支持。
8. 销售今日未领取数量，后续版本支持。
9. 分配备注。

主管选择销售并提交后，CRM 更新线索状态：

```text
assigned_pending_claim
已分配，待销售领取
```

同时记录：

```text
dispatch_manager_userid
assigned_sales_userid
assigned_at
dispatch_remark
```

### 5.4 推送销售领取卡片

主管分配成功后，CRM 给对应销售发送企业微信领取卡片。

销售卡片展示内容建议如下：

```text
主管张三分配给你一条新线索

来源：百度搜索
城市：上海
产品：企业服务套餐 A
客户：王先生
手机号：138****1234
要求：5 分钟内领取
```

卡片按钮：

```text
【领取】 【查看详情】
```

销售点击“领取”后，企业微信回调 CRM，CRM 校验点击人身份并更新线索状态。

### 5.5 销售领取线索

销售点击领取时，CRM 需要校验：

1. 当前点击人是否为被分配销售。
2. 当前线索是否处于“已分配，待销售领取”状态。
3. 当前线索是否未被其他人领取。
4. 当前线索是否未被主管转派。
5. 当前线索是否未关闭或无效。

校验通过后，CRM 更新：

```text
status = claimed
owner_userid = 当前销售 userid
claimed_at = 当前时间
```

### 5.6 卡片状态同步

销售领取成功后，需要同步更新两类卡片：

#### 主管卡片更新为：

```text
线索已领取

销售：李四
领取时间：2026-06-16 10:35
响应耗时：2 分钟
当前状态：待首次联系
```

按钮：

```text
【查看线索】
```

#### 销售卡片更新为：

```text
你已领取该线索

客户：王先生
当前状态：待首次联系
下一步：填写跟进
```

按钮：

```text
【填写跟进】 【查看客户】
```

### 5.7 销售填写跟进

销售点击“填写跟进”后，进入 CRM H5 页面。

跟进表单字段建议：

| 字段     | 类型   | 是否必填 |
| ------ | ---- | ---- |
| 跟进结果   | 下拉   | 是    |
| 客户意向   | 下拉   | 是    |
| 跟进备注   | 文本   | 是    |
| 下次跟进时间 | 时间选择 | 否    |
| 是否有效线索 | 单选   | 是    |
| 无效原因   | 下拉   | 条件必填 |
| 客户需求   | 文本   | 否    |
| 预计成交金额 | 数字   | 否    |

提交后，CRM 新增跟进记录，并更新线索当前阶段。

## 6. 线索状态设计

| 状态码                    | 状态名称   | 说明               |
| ---------------------- | ------ | ---------------- |
| new                    | 新线索    | CRM 刚接收，还未进入派发流程 |
| pending_dispatch       | 待主管分配  | 已通知主管，等待主管分配     |
| assigned_pending_claim | 已分配待领取 | 主管已分配销售，等待销售领取   |
| claimed                | 已领取    | 销售已确认领取          |
| following              | 跟进中    | 销售已填写至少一次跟进      |
| invalid                | 无效线索   | 销售标记无效，需记录原因     |
| converted              | 已转化    | 已成交或进入正式客户流程     |
| reassigned             | 已转派    | 主管重新分配给其他销售      |
| closed                 | 已关闭    | 线索流程结束           |

## 7. 操作权限规则

### 7.1 主管权限

主管可以：

1. 查看分配给自己负责范围内的线索。
2. 分配销售。
3. 查看销售领取状态。
4. 查看跟进状态。
5. 转派销售。
6. 关闭无效线索，是否允许可配置。

主管不可以：

1. 领取销售线索，除非同时具备销售角色。
2. 修改已成交线索的关键成交数据，除非具备管理员权限。

### 7.2 销售权限

销售可以：

1. 查看分配给自己的线索。
2. 领取线索。
3. 填写跟进记录。
4. 修改自己负责线索的跟进阶段。
5. 标记无效线索，是否需要主管审核可配置。

销售不可以：

1. 领取未分配给自己的线索。
2. 查看其他销售线索详情。
3. 修改线索来源、成本、渠道归因等关键字段。
4. 擅自转派线索。

## 8. 超时提醒规则

### 8.1 主管未分配提醒

线索进入 `pending_dispatch` 后，如果超过设定时间仍未分配，则发送提醒。

建议默认规则：

```text
3 分钟未分配：提醒主管
5 分钟未分配：再次提醒主管
10 分钟未分配：提醒上级主管或管理员
```

### 8.2 销售未领取提醒

线索进入 `assigned_pending_claim` 后，如果销售超过设定时间仍未领取，则发送提醒。

建议默认规则：

```text
3 分钟未领取：提醒销售
5 分钟未领取：提醒销售 + 主管
10 分钟未领取：主管可转派
```

## 9. 异常场景

| 场景             | 系统处理                          |
| -------------- | ----------------------------- |
| 主管重复点击分配       | 如果线索已分配，则提示当前状态，不重复分配         |
| 销售重复点击领取       | 如果已领取，则返回已领取状态                |
| 非分配销售点击领取      | 拒绝领取，提示无权限                    |
| 线索已被转派后原销售点击领取 | 拒绝领取，提示线索已转派                  |
| 企微卡片更新失败       | CRM 状态仍以数据库为准，补发新的状态通知        |
| 企微回调重复发送       | 通过事件 ID、task_id、lead_id 做幂等处理 |
| H5 页面身份获取失败    | 提示重新从企业微信打开                   |
| 销售离职或不可见       | 主管分配页不展示该销售                   |
| 主管不在线          | 可配置代理主管或上级主管兜底                |

## 10. 数据统计需求

本期至少需要记录以下指标：

| 指标      | 说明              |
| ------- | --------------- |
| 线索创建时间  | 广告线索进入 CRM 的时间  |
| 主管分配时间  | 主管完成分配的时间       |
| 销售领取时间  | 销售点击领取成功的时间     |
| 首次跟进时间  | 销售第一次填写跟进的时间    |
| 分配耗时    | 主管分配时间 - 线索创建时间 |
| 领取耗时    | 销售领取时间 - 主管分配时间 |
| 首次跟进耗时  | 首次跟进时间 - 销售领取时间 |
| 超时未分配数量 | 超过 SLA 未分配的线索数  |
| 超时未领取数量 | 超过 SLA 未领取的线索数  |
| 销售领取率   | 已领取线索数 / 分配线索数  |
| 线索转化率   | 成交线索数 / 有效线索数   |

## 11. 后台配置需求

CRM 管理端需要支持以下配置：

1. 企业微信 CorpID。
2. 企业微信自建应用 AgentID。
3. 企业微信自建应用 Secret。
4. 企业微信回调 Token。
5. 企业微信 EncodingAESKey。
6. 线索来源与主管映射关系。
7. 主管与销售团队映射关系。
8. 主管未分配提醒时间。
9. 销售未领取提醒时间。
10. 是否允许销售标记无效。
11. 是否允许主管转派。
12. 是否开启群机器人旁路通知。

## 12. 验收标准

### 12.1 主流程验收

1. 新线索进入 CRM 后，主管能在企业微信收到卡片。
2. 主管点击“分配线索”能打开 CRM H5 分配页。
3. 主管选择销售并提交后，CRM 状态变为“已分配待领取”。
4. 被分配销售能收到企业微信领取卡片。
5. 销售点击“领取”后，CRM 状态变为“已领取”。
6. 主管卡片能同步更新为“某某销售已领取”。
7. 销售卡片能同步更新为“已领取，可填写跟进”。
8. 销售点击“填写跟进”能进入 CRM H5 跟进页。
9. 销售提交跟进后，CRM 能新增跟进记录。
10. 所有关键动作均可在 CRM 操作日志中查询。

### 12.2 异常流程验收

1. 非分配销售无法领取线索。
2. 重复点击领取不会产生重复领取记录。
3. 线索已转派后，原销售无法领取。
4. 企业微信卡片更新失败时，CRM 主状态不受影响。
5. 企业微信重复回调时，CRM 不重复执行状态变更。
6. 主管超时未分配能收到提醒。
7. 销售超时未领取能收到提醒。

## 13. 后续迭代方向

1. CRM 自动推荐销售。
2. 主管一键确认推荐分配。
3. 按销售负载自动分配。
4. 按城市、产品、来源、销售转化率智能分配。
5. 销售响应 SLA 排行榜。
6. 高价值线索特殊提醒。
7. 无效线索主管审核。
8. 成交结果回流广告投放分析。
9. 企业微信群机器人播报关键状态。
