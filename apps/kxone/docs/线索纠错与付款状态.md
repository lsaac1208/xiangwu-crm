# 线索纠错与付款状态（2026-09-07）

## 用户操作

- 列表按姓名、负责人、日期和排序筛选后进入详情，详情返回和浏览器后退均保留原查询。详情刷新不会丢失返回位置。手机详情也提供“返回线索列表”。
- 辅助操作中的“标记成交”支持部分付款、已付全款、已退款。已成交后使用“编辑成交信息”补齐尾款、纠正金额或登记退款。
- “累计收款金额”是实际累计收到的款项，包含后来退还的部分；“累计退款金额”是实际累计退还的款项。净收款等于两者之差。金额最多两位小数，范围为 0.01–999999999.99 元；退款不能超过收款。
- 无效线索可通过“恢复为有效线索”恢复到原来的邀约或谈单阶段并继续跟进；没有负责人的历史线索恢复为待分配。恢复后需重新安排回访。
- 当前业务阶段的负责人、主管和管理员可以纠正成交、恢复无效及编辑终态线索的客户资料；调度员和无关业务人员不能修改。
- 修改成交和恢复无效必须填写原因。业务过程记录操作者、原因及修改前后状态、金额，保留原无效跟进记录和首次成交时间。数据版本冲突时拒绝覆盖并保留表单。

## 数据兼容与统计

新增迁移 `000025_lead_payment_details.sql`，仅增加 `payment_status`、`refund_amount`，不删除或重写旧金额。历史成交记录付款状态留空，显示“已成交 · 待确认付款”，由负责人核对后选择状态。

业务状态仍为 converted，三个付款状态为 partial / paid / refunded，保留既有成交列表及历史转化数量口径（包括后来退款的成交记录）。统计中的净收款和平均净收款扣除累计退款；此页面不是按退款发生日期统计的财务流水账。

API：原 `POST /api/leads/:id/convert` 增加付款状态和退款金额，兼容旧客户端缺省状态；新增 `PATCH /api/leads/:id/deal`、`POST /api/leads/:id/restore-invalid`，两者必须携带 `expected_version` 和 `reason`。更新与审计在一个事务中完成，并使用业务版本和资料版本进行乐观锁校验。

## 部署与回退

上线前使用 SQLite backup API 备份数据库，构建独立 release，切换 `/opt/kxone/current` 并检查服务、迁移和数据库完整性。原 release 和数据库备份均保留。

本次 schema 只增加兼容字段。若需回退应用，将 current 原子切换回原 release 并重启 CRM 服务，保留新列及操作记录；正常应用回退不需要覆盖数据库。仅在确认数据库受损、并已评估备份之后的新增数据时才恢复数据库备份。
