# AI 分析第二阶段：固定指标 + 模型只写说明

日期：2026-10-14　状态：实施中（分支 `codex/crm-agent-20261008`）

## 背景

自由分析（模型自写 SQL、服务端对正文数字做绑定/引用校验、最多一次纠正）在真实模型验收中反复因
“未绑定数字”“因果断言”“全称范围”被整轮拒绝（v28–v31，A13/A21）。问题不在数据，而在于让模型
既取数又写数字。第二阶段改为：**数字只由服务端固定指标产生，模型只负责选指标和写不含数字的解读**。

## 设计

1. **固定指标目录**（`internal/agent/metrics.go`）：每个指标是服务端预定义的只读 SQL 模板，运行在
   本轮脱敏快照上（与原分析同一快照、同一 SQLite 只读授权器），参数全部用占位符绑定。
2. **筛选参数**（白名单，每个指标声明可用项）：`date_from`/`date_to`（上海日期）、`sources`、
   `exclude_sources`、`owner`（员工姓名或企业微信账号）、`customer`（如“客户#2”）、
   `keyword`（跟进关键词）、`due_before`（上海时刻）。未声明的参数被拒绝或忽略并记录。
3. **模型的两步**（最多 2 次模型调用，单轮费用远低于自由分析）：
   - 第 1 次：工具 `select_metrics({selections:[{metric_id,params}]})`（最多 3 个），或
     `cannot_answer({reason})`（题目超出指标范围，如 ROI、家庭去重）。
   - 服务端执行指标、保存结果、按模板生成表格/图表块。
   - 第 2 次：模型看到结果后调用 `write_interpretation({text})` 写解读。
4. **解读降级而非失败**：解读先经快照脱敏；含阿拉伯/全角数字、中文数量（如“两条”）、百分号或
   因果断言（导致/造成/因为/由于/所以/因此/证明…）的句子被服务端删除；全部删除时显示固定提示
   “请以上方表格为准”。降级记录 `interpretation_downgraded` 事件，不导致整轮失败。
5. **隐私**：保留供应商响应的已知客户名/联系方式检查。第 1 次调用命中则本轮不采用模型选择并提示
   手动选择指标；第 2 次命中则丢弃解读，表格照常发布。
6. **数字、表格、图表与导出**全部来自服务端结果；最终块含 `sources.result_ids`，现有导出
   （Excel/报告）无需改动即可工作。
7. **模型不可用时的退化**：`POST /api/agent/conversations/:id/metric-runs`（`metric_id`+`params`）
   不调用模型、不占模型额度，AI 开关关闭时也可用；`GET /api/agent/metrics` 返回指标目录。
   模型调用失败时运行以“模型暂不可用，可在下方常用指标中手动选择”结束。
8. **自由分析**：代码保留，由 `Config.FixedMetrics` 控制；生产默认固定指标，
   仅当环境变量 `KXONE_AGENT_FREE_ANALYSIS=1` 时恢复自由分析（不建议）。
9. **权限**：沿用 AI 分析现有可见范围——仅在职的主管/管理员可用，会话归属与运行中权限复核不变；
   快照本身的字段投影与脱敏规则不变。
10. **依据链接**：记录类指标附 `record_type/record_id/lead_id` 列，回答依据区可直接打开对应线索。
11. **前端**（`AgentChat.vue`）：输入框上方提供“常用指标”快捷入口（来源分布、当前归属、跟进按
    操作人、首跟时效、回访待办等），点击即手动运行；AI 关闭时页面仍可使用快捷指标。

## 第三阶段：像正常聊天一样回答（2026-10-14）

起因：生产对话 `02731d71…` 问“上周共有几条线索进来？”被整轮拒绝。根因是选指标阶段对模型工具参数整段做
已知联系方式子串匹配，而联系方式词典收录了无长度下限的原值（生产有 3 字节手机号、历史掩码 `*` 等），
日期参数中的片段被误判为 `known_contact`；且任一命中即整轮失败、不执行指标。

1. **结构化参数单独校验**（`metrics_guard.go`）：`metric_id` 只认目录枚举，日期须 `YYYY-MM-DD` 且为真实日期，
   `due_before`/`customer` 走正则；这些值不再参与联系方式子串检查。`owner`/`sources`/`keyword` 逐个检查：
   与快照中真实来源或员工完全一致者放行，其余命中已知联系方式/客户名/凭证/脱敏规则的**只丢弃该参数**，
   指标照常执行，事件 `metric_params_dropped` 只记参数名与规则类别。`cannot_answer` 理由与正文仍做完整检查，
   命中则丢弃文本。
2. **联系方式词典门槛**（`redact.go`）：含 `*`（掩码）或字母数字少于 6 个的值（`*`、`无`、`202`）不入词典。
3. **从不因可算出的数字而失败**：模型不可用、额度不足、未选指标、对常见问题拒答、指标参数无效时，由服务端
   解析器（`metrics_chat.go`：上周/本周/本月/上月/昨天/今天/近N天/M月D日到M月D日 + 关键词→指标）选指标并
   作答（事件 `metric_fallback`）；无法理解时给友好的改问建议，状态 completed。“你好”等寒暄不调用模型。
   超范围问题（ROI、去重、修改数据等）尊重模型的 `cannot_answer`。
4. **直接回答在前**：每个指标有服务端模板，从结果单元格取数生成口语句子，如“上周（10月5日–11日）一共进来
   5 条新线索。”“本月按来源看，「好学校」最多，共 4 条……”“目前普通回访待办「员工乙」最多，共 3 项……”。
   之后才是可选解读，最后是口径行“- 指标：…（条件）”。
5. **新增指标**：`lead_count`（区间新增线索总数）、`deal_count`（按成交日期统计单数与金额）。目录共 15 项。
6. **追问沿用条件**：服务端从上一轮 `metric_selected` 事件读取指标与条件并写入提示词；本轮问题没有时间短语、
   模型也未填日期时，服务端补上上一轮日期（及来源/排除来源/人员筛选，问题含“全部/所有/不限”时不补），
   记 `context_inherited`。
7. **解读可选**：只有分析型问题（比较/为什么/是否/证明/表现…）才发第二次模型调用；解读失败或被拦截时静默省略，
   不再显示“暂不可用/已省略”提示。第二次调用不回放第一次的工具参数，只发送服务端结果。
8. **选指标模型**：`KXONE_AGENT_METRIC_SELECT_MODEL=fallback` 时选指标阶段优先用已配置的备用模型（如 DeepSeek），
   失败再回主模型；默认仍为主模型（生产近 14 天主模型调用 0 失败，且生产未配置备用模型）。
9. **验收**：新数据集 `daily-v1`（`Agent-Daily-Fixture.json`，gold-v1 + 6 条按运行日相对日期的线索，含短联系方式
   `*`/`202`/`无`），题 D01–D07（你好、上周几条、本月来源、昨天新增、待办最多、本月成交、三轮追问），
   主模型与 DeepSeek 各跑 3 次；原 M08/M13/M21/M26 继续通过。旧代码在该数据上复现生产同款
   `tool_arguments/known_contact` 拒绝。

## 第四阶段：生产“今天几条”失败的根治与界面精简（2026-10-14）

根因：快照查询会对绑定参数做文字脱敏。生产里有短客户值（如“20”“26”），刚好是日期的一部分，日期“2026-10-14”就被改成了客户编号。发给模型的系统提示词整段脱敏，同样把日期改坏了，模型照抄后，参数检查以“格式错误”为由丢掉日期，结果按全部数据计数。另外，服务端解析器只在模型失败时才兜底。

修复：
1. 固定指标的 SQL 和结构化参数改走 `Snapshot.QueryFixed`，不再做文字脱敏（负责人、关键词这类自由文本仍在 runMetric 里脱敏）；系统提示词只对用户规则部分做脱敏。
2. 脱敏收紧：少于 2 个汉字且少于 6 位字母数字的客户名只按独立词替换；纯数字短值紧挨日期或计量单位（年月日、条、单等）时不替换。
3. 解析器优先：解析出的时间一律覆盖模型日期；解析器有把握而模型选了无关指标时，改用解析器的指标（事件 `parser_override`）；新增纠正式追问（“不是，单单今天”）。
4. 兜底：模型日期被丢弃、解析器又没有时间时，不再静默按全部数据回答（事件 `dates_unresolved`）；不限日期时，回答明确写“未限定日期”。
5. 验收：新增数据集 `prodcopy-v1`（服务器本地在线备份副本，不出服务器、用完即删）和 `scripts/agent_prodcopy_check.py`（口语问法 × 2 轮，与只读 SQL 逐项对数，并核对实际执行参数）。
6. 界面：回答只剩自然语言，去掉“- 指标：”行；表格默认直接显示；数据时点、分析范围、SQL、绑定参数、依据记录都收进默认折叠的“依据”。
