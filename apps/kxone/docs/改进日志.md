# 改进日志

## 2026-07-07 - 生产清查问题修复

- 生产启动前强制校验 `SERVER_PUBLIC_BASE_URL`、`JWT_SECRET`、`FIELD_ENCRYPTION_KEY`、`MOBILE_HASH_KEY`，避免关键安全配置漏配后半残运行。
- 手机号精确搜索 HMAC 改为独立 `MOBILE_HASH_KEY`，不再与 AES-GCM 字段加密密钥共用；历史 hash 可通过 `cmd/tools/encrypt_legacy_mobile` 重算。
- 卡片领域层移除硬编码公网域名，worker 统一使用 `SERVER_PUBLIC_BASE_URL` 注入卡片按钮链接。
- 企业微信事件回调处理器改为显式依赖注入，不再通过 `gin.Context` 隐式传递 `CallbackHandler`。
- 广告线索默认主管示例改为占位符，代码不再内置真实企业微信 UserID；无认证入口限流器补充单实例约束说明。
- server 路由装配引入手写 `serverContainer`/`handlerContainer`，并按 API 域拆分注册函数；暂不引入 wire，保持早期生产期的可读性和低迁移成本。
- Redis cache adapter 从 `github.com/go-redis/redis/v8` 迁移到 Asynq 已使用的 `github.com/redis/go-redis/v9 v9.0.3`，消除双 Redis 客户端依赖。
- PC 统计看板重做为独立工作台布局：新增通用 `kx-desktop-*` 样式基础、KPI 指标区、筛选工具条、销售/来源/待跟进表格化展示；企微移动端保持原交互。
- 新建线索、添加跟进、后台配置接入统一 PC header 与工作台样式；后台企业微信配置改为左右两栏，编辑弹窗在 PC 下居中定宽。
- PC 线索列表二次优化：迁移到统一 `kx-desktop-*` 工作台结构，强化状态筛选、搜索、刷新、总数反馈和表格列宽；线索详情改为主信息列 + 右侧处理侧栏，跟进记录固定在主列展示。
- 修复卡片补偿重复补发：失败扫描只处理 `update_failed`，过期旧卡片补发成功后标记为 `replaced`，避免历史 `expired` 任务每 5 分钟重复补发。
- 线上清理 15 条历史可重复补偿卡片任务，清理前已备份数据库到 `/opt/kxone/backups/`。
- 生产默认 GORM 日志级别改为 `warn`，可通过 `DB_LOG_LEVEL` 覆盖，避免完整 SQL 和 `response_code` 等字段持续写入日志。
- HTTP handler 错误响应统一收敛为稳定错误码，内部错误详情写服务日志；广告入口保持 `ok:false` 响应结构。
- 统计看板派发/领取逾期口径读取后台提醒配置；提醒规则禁用时，对应逾期提醒计数不再按旧默认值计算。
- nginx 静态首页补齐 CSP、X-Frame-Options、nosniff、Referrer-Policy、Permissions-Policy 等安全响应头。

## 2026-07-06 - 完整手机号精确搜索

- 线索新增 `customer_mobile_hash` HMAC 索引字段，写入/更新线索时由仓储层根据明文手机号生成，接口响应不暴露该字段。
- 列表关键词搜索保留原有姓名、渠道、产品、脱敏手机号尾号等模糊匹配；当关键词看起来是完整手机号时，额外用 HMAC 等值匹配支持完整手机号精确搜索。
- HMAC 使用独立 `MOBILE_HASH_KEY` 作为密钥，避免存储可逆手机号或明文 hash；`+86 13912345678` 与 `13912345678` 会归一化为同一手机号。
- 新增迁移 `000002_add_customer_mobile_hash.sql` 创建字段和索引；历史数据通过 `cmd/tools/encrypt_legacy_mobile` 维护工具回填 hash。

## 2026-06-30 - Asynq 队列改造 + 监控系统

### 改造背景
将异步 goroutine 改为 Asynq 队列，增强可靠性和可观测性。

### 核心改动

#### 1. Asynq 任务队列替换 goroutine

**改动文件**：
- `internal/transport/worker/payloads.go`（新增）：定义任务载荷类型
- `internal/transport/worker/client.go`：新增 `EnqueueUpdateCard`、`EnqueueSendCard` 方法
- `internal/transport/worker/task_handler.go`：新增 `HandleSendCard`、`HandleUpdateCard` 处理器
- `internal/transport/worker/server.go`：注册新任务类型到队列
- `internal/usecase/assign_lead.go`：替换 goroutine 为 taskQueue.EnqueueUpdateCard/EnqueueSendCard
- `internal/usecase/claim_lead.go`：同上
- `cmd/server/main.go`：注入 worker client 到 UseCase

**改进效果**：
- ✅ 任务持久化到 Redis，进程重启不丢失
- ✅ 自动重试机制（指数退避）
- ✅ 任务优先级队列（cards 队列优先级高）
- ✅ 可通过 Asynq CLI 监控任务状态

#### 2. 监控指标系统

**新增文件**：
- `pkg/metrics/metrics.go`：监控指标收集器

**监控指标**：
```go

- card_update_total/success/failed        // 更新总数/成功/失败
- card_update_success_rate                // 更新成功率
- card_update_avg_latency_ms/p95_latency_ms

// 状态转换指标
- state_transition_total/success/failed   // 状态转换总数/成功/失败
- state_transition_success_rate           // 状态转换成功率

// 业务指标
- lead_assign_total                       // 线索分配总数
- lead_claim_total/failed                 // 线索领取总数/失败数
- lead_claim_success_rate                 // 领取成功率
```

**监控端点**：
```bash

```

**集成位置**：
- `internal/transport/worker/task_handler.go`：卡片发送/更新时记录
- `internal/usecase/assign_lead.go`：状态转换、线索分配时记录
- `internal/usecase/claim_lead.go`：状态转换、线索领取时记录

#### 3. 接口抽象

**新增接口**：
```go
// internal/usecase/assign_lead.go
type TaskQueue interface {
    EnqueueUpdateCard(ctx context.Context, leadID int64, cardScene string) error
    EnqueueSendCard(ctx context.Context, leadID int64, receiverUserID, cardScene string) error

```

**好处**：
- UseCase 层不依赖具体实现，便于单元测试
- 可以 mock TaskQueue 进行测试
- 符合依赖倒置原则
