# 技术设计补充文档

## 1. 并发控制设计

### 1.1 线索领取的原子性保障

**问题**：销售领取时，可能存在主管转派与销售领取的竞态条件。

**方案**：数据库乐观锁 + 原子更新

```sql
-- leads 表增加 version 字段
ALTER TABLE leads ADD COLUMN version INT NOT NULL DEFAULT 0;

-- 领取时的原子更新
UPDATE leads
SET owner_userid = :sales_userid,
    claimed_at = NOW(),
    status = 'claimed',
    version = version + 1,
    updated_at = NOW()
WHERE id = :lead_id
  AND assigned_sales_userid = :sales_userid
  AND status = 'assigned_pending_claim'
  AND version = :expected_version;
```

**失败场景处理**：
- 更新影响行数为 0 → 重新查询线索状态 → 返回具体错误原因
- 不使用分布式锁，避免额外依赖和锁超时问题

### 1.2 主管转派场景

**数据流**：
```
主管点击转派 → Dispatch Service 校验权限
                ↓
          更新 assigned_sales_userid + version + 1
                ↓
          原销售卡片更新为"已转派"
                ↓
          新销售收到领取卡片
```

**原子更新条件**：
```sql
UPDATE leads
SET assigned_sales_userid = :new_sales_userid,
    status = 'assigned_pending_claim',
    version = version + 1,
    updated_at = NOW()
WHERE id = :lead_id
  AND dispatch_manager_userid = :manager_userid
  AND status IN ('assigned_pending_claim', 'claimed')
  AND version = :expected_version;
```

## 2. 企业微信卡片状态同步设计

### 2.1 问题定义

企业微信卡片更新可能失败（网络、权限、response_code 过期），但不能影响 CRM 核心状态。

### 2.2 状态分离原则

**CRM 状态（真实状态）**：
- 存储在 `leads` 表
- 所有业务判断以此为准
- 状态变更必须成功

**卡片状态（展示状态）**：
- 存储在 `wecom_card_tasks` 表
- 仅用于跟踪展示一致性
- 更新失败不回滚业务状态

### 2.3 卡片任务状态机

```
wecom_card_tasks.card_status:

sent              → 已发送，等待首次更新
updating          → 正在更新中
updated           → 更新成功
update_failed     → 更新失败，待重试
expired           → response_code 已过期
replaced          → 已被新卡片替代
```

### 2.4 同步策略

#### 主路径（实时同步）
```
CRM 状态变更成功
    ↓
尝试更新企业微信卡片
    ↓
成功 → card_status = 'updated'
失败 → card_status = 'update_failed'，记录失败原因
```

#### 补偿路径（定时重试）
```
定时任务扫描 card_status IN ('update_failed', 'expired')
    ↓
判断 response_code 是否过期
    ↓
过期 → 重新发送新卡片，旧卡片标记 'replaced'
未过期 → 重试更新，最多 3 次
    ↓
3 次仍失败 → 发送新卡片
```

### 2.5 wecom_card_tasks 表字段补充

```sql
ALTER TABLE wecom_card_tasks ADD COLUMN version INT NOT NULL DEFAULT 0;
ALTER TABLE wecom_card_tasks ADD COLUMN retry_count INT NOT NULL DEFAULT 0;
ALTER TABLE wecom_card_tasks ADD COLUMN last_error TEXT;
ALTER TABLE wecom_card_tasks ADD COLUMN next_retry_at DATETIME;
```

### 2.6 response_code 生命周期管理

**规则**：
- 企业微信返回的 response_code 有效期约 1 小时
- 每次发送卡片时记录 `response_code_expire_at = NOW() + INTERVAL 50 MINUTE`
- 更新前检查是否过期，过期则重发新卡片

**逻辑伪代码**：
```javascript
function updateCard(lead_id, new_content) {
  card_task = get_latest_card_task(lead_id, card_scene);
  
  if (card_task.response_code_expire_at < NOW()) {
    // response_code 已过期，发送新卡片
    return sendNewCard(lead_id, new_content);
  }
  
  result = wecom_api.update_card(
    response_code: card_task.response_code,
    content: new_content
  );
  
  if (result.success) {
    update_card_task_status('updated');
  } else if (result.error == 'invalid_response_code') {
    // response_code 实际已失效，重发新卡片
    return sendNewCard(lead_id, new_content);
  } else {
    update_card_task_status('update_failed');
    schedule_retry();
  }
}
```

## 3. OAuth 登录态管理设计

### 3.1 登录流程

```
用户从企业微信卡片点击 H5 链接
    ↓
CRM 前端检查 localStorage 是否有 access_token
    ↓
无 token 或 token 过期 → 重定向到企业微信 OAuth
    ↓
企业微信回调 /api/auth/wecom/callback?code=xxx
    ↓
CRM 后端用 code 换取 UserID
    ↓
查询 crm_wecom_user_bindings 表获取 crm_user_id
    ↓
生成 JWT：{ user_id, wecom_userid, role, exp }
    ↓
返回前端：{ access_token, refresh_token, expires_in }
    ↓
前端存储 token，跳转到原目标页面
```

### 3.2 Token 设计

**Access Token（短期）**：
- 有效期：2 小时
- 存储：前端 localStorage
- 用于：所有 API 请求的 Authorization header

**Refresh Token（长期）**：
- 有效期：7 天
- 存储：前端 localStorage + 后端 Redis
- 用于：access_token 过期后自动刷新

**JWT Payload**：
```json
{
  "user_id": 123,
  "wecom_userid": "zhangsan",
  "role": "sales",
  "department_id": 10,
  "iat": 1687766400,
  "exp": 1687773600
}
```

### 3.3 Token 刷新机制

**前端拦截器**：
```javascript
// axios 请求拦截器
axios.interceptors.response.use(
  response => response,
  async error => {
    if (error.response.status === 401) {
      // access_token 过期，尝试刷新
      const newToken = await refreshAccessToken();
      if (newToken) {
        // 重试原请求
        error.config.headers.Authorization = `Bearer ${newToken}`;
        return axios.request(error.config);
      } else {
        // refresh_token 也过期，重新 OAuth
        redirectToWeCom();
      }
    }
    return Promise.reject(error);
  }
);
```

### 3.4 后端 Token 校验

```javascript
// JWT 中间件
function authMiddleware(req, res, next) {
  const token = req.headers.authorization?.split(' ')[1];
  
  if (!token) {
    return res.status(401).json({ error: 'missing_token' });
  }
  
  try {
    const decoded = jwt.verify(token, JWT_SECRET);
    
    // 检查用户是否被禁用
    const user = getUserById(decoded.user_id);
    if (user.status !== 'active') {
      return res.status(403).json({ error: 'user_disabled' });
    }
    
    req.user = decoded;
    next();
  } catch (err) {
    if (err.name === 'TokenExpiredError') {
      return res.status(401).json({ error: 'token_expired' });
    }
    return res.status(401).json({ error: 'invalid_token' });
  }
}
```

## 4. 幂等性设计

### 4.1 企业微信回调幂等

**问题**：企业微信可能重复发送回调事件。

**方案**：基于 event_id + task_id 的幂等键

```javascript
// 回调处理入口
async function handleWeCom Callback(event) {
  // 构造幂等键
  const idempotent_key = `wecom:callback:${event.task_id}:${event.from_userid}:${event.event_key}`;
  
  // Redis SETNX，有效期 10 分钟
  const acquired = await redis.set(
    idempotent_key,
    '1',
    'EX', 600,
    'NX'
  );
  
  if (!acquired) {
    // 重复回调，直接返回成功
    return { success: true, message: 'duplicate_callback' };
  }
  
  // 记录回调日志
  await saveCallbackLog(event);
  
  // 执行业务逻辑
  const result = await processEvent(event);
  
  return result;
}
```

### 4.2 领取动作幂等

**多重保障**：
1. Redis 幂等键（快速拒绝重复请求）
2. 数据库原子更新（最终幂等保证）
3. 回调日志去重查询

```javascript
async function claimLead(lead_id, sales_userid, task_id) {
  // 第一层：Redis 幂等键
  const claim_key = `lead:claim:${lead_id}:${sales_userid}`;
  const acquired = await redis.set(claim_key, '1', 'EX', 60, 'NX');
  
  if (!acquired) {
    // 1 分钟内重复领取，直接查询当前状态返回
    const lead = await getLeadById(lead_id);
    return buildClaimResponse(lead);
  }
  
  // 第二层：数据库原子更新
  const affected = await db.execute(`
    UPDATE leads
    SET owner_userid = ?,
        claimed_at = NOW(),
        status = 'claimed',
        version = version + 1
    WHERE id = ?
      AND assigned_sales_userid = ?
      AND status = 'assigned_pending_claim'
  `, [sales_userid, lead_id, sales_userid]);
  
  if (affected === 0) {
    // 更新失败，查询原因
    const lead = await getLeadById(lead_id);
    return buildClaimError(lead, sales_userid);
  }
  
  // 领取成功，异步更新卡片
  await updateCardsAsync(lead_id);
  
  return { success: true };
}
```

## 5. 异步任务设计

### 5.1 任务队列选型

**推荐方案**：Redis + Bull（Node.js）/ Celery（Python）

**理由**：
- 轻量级，无需额外组件
- 支持延迟任务、重试、优先级
- 可视化监控工具完善

### 5.2 任务类型划分

#### 立即执行任务（高优先级）
- 发送企业微信卡片
- 更新企业微信卡片
- 领取成功通知

#### 延迟执行任务
- 超时未分配提醒（延迟 3 分钟）
- 超时未领取提醒（延迟 3 分钟）

#### 定时扫描任务
- 卡片更新失败重试（每 5 分钟）
- 卡片 response_code 过期处理（每 10 分钟）

### 5.3 任务重试策略

**卡片发送/更新任务**：
- 最多重试 3 次
- 重试间隔：10s, 30s, 60s（指数退避）
- 3 次失败后记录错误日志，人工处理

**回调处理任务**：
- 不重试（幂等保证 + 日志记录）

## 6. 监控与告警设计

### 6.1 关键指标

**业务指标**：
- 线索进入 CRM 到主管收到卡片的延迟（P50/P95/P99）
- 主管分配率（已分配 / 总线索）
- 销售领取率（已领取 / 已分配）
- 平均主管分配耗时
- 平均销售领取耗时
- 超时未分配数量（实时）
- 超时未领取数量（实时）

**技术指标**：
- 企业微信消息发送成功率
- 企业微信回调处理成功率
- 卡片更新成功率
- OAuth 登录成功率
- API 响应时间（P50/P95/P99）
- 数据库查询耗时
- 任务队列堆积数量

### 6.2 告警规则

**P0（紧急）**：
- 企业微信消息发送成功率 < 95%，持续 5 分钟
- OAuth 登录成功率 < 90%，持续 5 分钟
- 超时未分配数量 > 50，持续 10 分钟

**P1（重要）**：
- 卡片更新成功率 < 90%，持续 10 分钟
- 任务队列堆积 > 1000，持续 15 分钟
- P95 API 响应时间 > 3s，持续 10 分钟

**P2（一般）**：
- 销售领取率 < 80%，持续 1 小时
- 主管分配率 < 90%，持续 1 小时

## 8. 安全加固

### 8.1 敏感信息加密

**需要加密的字段**：
- `leads.customer_mobile`（原始手机号）
- 企业微信 Secret、Token、EncodingAESKey
- JWT Secret

**加密方案**：
- 对称加密：AES-256-GCM
- 密钥管理：环境变量 + KMS（生产环境）

### 8.2 权限校验层级

**第一层：JWT 校验**（中间件）
- 验证 token 有效性
- 检查用户状态

**第二层：角色校验**（路由层）
- 主管才能访问分配接口
- 销售才能访问领取接口

**第三层：数据权限校验**（业务层）
- 主管只能分配自己负责范围内的线索
- 销售只能领取分配给自己的线索

**第四层：操作幂等校验**（业务层）
- 防止重复领取
- 防止状态冲突

### 8.3 手机号脱敏规则

**企业微信卡片**：始终脱敏
```
138****1234
```

**H5 详情页**：根据角色权限
- 主管：完整手机号
- 销售（已领取）：完整手机号
- 销售（未领取）：脱敏手机号

**API 返回**：
```json
{
  "customer_mobile": "13812345678",        // 原始
  "customer_mobile_masked": "138****5678"  // 脱敏
}
```

前端根据权限选择展示哪个字段。
