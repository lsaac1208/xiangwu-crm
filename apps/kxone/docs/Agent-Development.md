# CRM AI 分析：开发与维护说明

本文说明对话式分析模块的实现边界与维护契约。验收是否完成以 `Agent-Acceptance.md` 及本次交付证据为准；评测集本身不代表真实模型已通过。

## 产品与数据流程

“AI 分析”使用主管/管理员身份访问全体招生业务数据，各人的会话按不可变账号 ID 独立保存。管理员身份不授予读取他人对话、结果、证据或导出的权利。客户姓名和联系方式由本地脱敏后再送云模型，员工和来源作为业务维度保留。

分析一次问题创建独立运行：读取短事务业务快照 → 关闭业务源连接 → 在脱敏快照查询/检索 → 保存实际结果及回答 → 删除临时快照。模型调用期间不持有业务库读取事务。业务表不因分析而修改；新增表只保存分析会话、运行、结果、规则及费用。

后端提供数据字典、只读 SQL、文本检索和受控结果展示工具。回答可以组合 Markdown、表格、图表与来源；数字必须来自真实结果。表格/图表引用结果 ID，不接受模型生成任意行列数据。每一轮查询覆盖全量匹配数据，明细分页单独记录总数、返回数和截断状态。

旧统计页地址跳转到 AI 分析；旧后端统计接口暂留供已打开页面兼容，新 Agent 不调用其一万条上限统计逻辑。线索列表的业务待办和原有业务功能继续使用现行规则。

## 配置与运行约束

服务端环境变量：

| 变量 | 说明 |
|---|---|
| `AGENT_ENABLED` | 新分析开关，默认关闭；开关关闭仍应允许读取已有会话和导出。 |
| `AGENT_BASE_URL` | 官方兼容接口地址，填写完整 `/chat/completions` 路径；生产只接受 HTTPS 公网接口。 |
| `AGENT_API_KEY` | 可选的初始模型密钥；运行期也可由管理员在网页系统设置中配置。禁止写入 Git 或输出日志。 |
| `AGENT_MODEL` | 默认 `qwen3.8-max`；可设为 `deepseek-v4-pro` 以 DeepSeek 为主（自动使用非思考工具模式），另一供应商在系统设置配为备用。更换模型需重新真实评测和核对价格。 |
| `AGENT_STORAGE_DIR` | 私有快照/导出目录，目录权限 `0700`，文件权限 `0600`；不要加入静态资源目录。 |

管理员可以在 CRM 网页“系统设置”配置完整 URL、API Key、模型名与输入/输出费率，并主动发起连通测试。密钥仅通过鉴权 HTTPS 写入，服务端采用现有 FieldProtector 加密保存；读取设置只返回“已配置”状态，不能返回原密钥或可逆片段。留空 Key 表示保留，删除使用显式清除操作；版本冲突保留输入。连通测试不发送业务数据，但属于付费调用，必须预留和结算预算。

初始月预算 300 元，单轮 3 元、180 秒、12 次模型调用（2026-10-13 由 8 上调，费用上限不变）、12 次数据工具调用，SQL 最长 5 秒；全局两项运行、每个账号一项。金额统一使用整数微元，一元为 `1_000_000` 微元。价格配置以每百万 token 的微元保存：输入 12 元/百万保存为 `12_000_000`，输出 36 元/百万保存为 `36_000_000`；调用成本按 token 数乘费率再除以一百万、向上取整。价格版本与模型调用一同保存；新模型不能自动沿用原价格。

生产端点不能指向本机或内网；测试用可控模型仅在隔离测试装配允许。模型请求需显式设置输出 token 上限，思考 token 的计费上限也必须受约束。未知计费输出不能以经验倍数视为可靠上限。

DeepSeek 从新运行/新供应商执行段首请求明确使用 `thinking.type=disabled`，通过官方非思考工具协议保留完整工具调用与回复。底层显式开启思考模式的协议能力仍完整保留，不删除或补空已有推理字段；原生推理不持久化或输出。参见 [DeepSeek 思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/) 与 [工具调用](https://api-docs.deepseek.com/zh-cn/guides/tool_calls/)。模式调整必须重新做真实语义验收，不能据无推理字节就认定答案正确。

配置备用时主阶段只定锚一次，生产 180 秒总期限内主阶段窗口为 90 秒，保护备用至少 60 秒的执行空间；前续成功调用及中间工具操作不刷新该窗口。实际主请求同时受单次 60 秒及窗口期限约束；只剩最后一次调用时，不再为无法额外调用的备用截断这一请求。派发前窗口耗尽可将尚未使用的调用交给备用，事件原因是 `primary_time_window`，不同于实际供应商失败的 `primary_unavailable`。两者均复用原任务、快照、结果与累计预算，不自动重新查询已成功结果；账号失效、取消、全局到期优先停止。短总期限沿同比例缩放窗口。

SSE 用同源鉴权流式路由，并独立于普通十秒 Axios 请求。十五秒心跳，事件游标用于断线恢复。服务端任务不会因为浏览器重连而再调用模型，停止生成必须取消后台上下文。服务重启把旧运行标为中断，保留未知费用，不自动重试。

## 预算账本

`internal/agent/budget.go` 提供以下接口：

```go
NewBudget(db *gorm.DB) *Budget
Reserve(ctx, runID, accountID, amountMicro, monthlyLimitMicro, runLimitMicro, priceVersion, now) (reservationID, error)
Settle(ctx, reservationID, actualMicro, Usage) error
Summary(ctx, now) (BudgetSummary, error)
```

每次模型调用单独预留，不能只在问题开始时检查一次额度。`Reserve` 使用单条条件写入检查月累计和运行累计，预算依据“已结算核算金额 + 未结算预留”决定。SQLite 先获取写锁再计算条件，多个连接或多个 Budget 实例都不会穿透剩余额度；不依赖进程内锁。

`ai_budget_reservations` 保存调用 ID、run ID、账号、上海月份、状态、原预留金额、实际金额、输入/输出 token、价格版本和创建/结算时间。月归属创建后不变。一个九月调用在十月结算，仍计入九月。

结算使用条件更新，只能把 `reserved` 变成 `settled`；相同金额和用量的重复结算返回成功，不同用量返回冲突。零输入、零输出视为用量未知，保留原预留。已知实际金额大于原预留时仍准确记录实际费用，但返回异常，暂停继续调用并进行价格/输出上限核对；不能用旧估计金额隐藏已发生的超额。不能因取消、超时、重启或供应商未返回用量就把费用归零。

唯一例外是服务端仍处于 `callModel` 之前、可以证明根本没有派发的调用：本地写库等待或权限校验使窗口到期时，私有调度路径把同运行预留标记为 `not_sent`。保留原始预留金额和月份，不伪造 token 或供应商用量；这类记录不计费用、已调用或未知调用。该操作不在重启清理、未知费用处理、供应商异常或公开接口中使用；一旦进入供应商调用路径，仍按已结算或未知预留处理。写入无法确认时停止，不能以推测释放费用。旧安全应用回滚后会保守地将此新状态计入预留，不会造成超预算。

管理员预算页面显示已结算、仍预留、当前月总占用、调用数和 token 用量；达到 80% 提醒，满额停止新分析。费用核对不能把未知调用忽略。每次调用前的预算配置、原预留及实际用量是后续账单审计依据。

已结算金额由实际 token 用量乘本轮配置单价核算，属于内部费用账本，不直接等同供应商最终扣费。首版按配置标准价核算，缓存折扣、促销、赠送额度及账单调整可能使实际扣费不同；展示和交付注明“按配置单价核算，需与供应商账单核对”，没有账单证据不能把差额写成零。

管理员设置另展示本月保留会话中的分析任务失败率与成功任务平均耗时，按上海创建月份统计；删除会话后相应任务不再计入。取消和额度不足等状态单列，缺失或非法时长不按零处理；该指标不是模型调用失败率。模型调用的供应商声明标识、响应ID、用量及预留金额记录在私有运行的 `model_usage` 事件中，不包含密钥或推理内容。

## 证据、快照和导出

`Result` 保存列、行、SQL、匹配总数、返回数、截断状态、覆盖说明、数据时点和来源。回答应附结果/记录依据；引用缺失结果时必须失败，不能生成替代的空表。

最终引用由 `select_final_results({result_ids: [...]})` 明确选择，不能根据最后一次查询或来源卡片数量猜测。最终 `sources` 回答块保存 `result_ids`：`null` 表示历史未声明，`[]` 表示本次明确不采用数据。`GET /api/agent/runs/:id` 返回 `result_selection`，区分 `explicit`、`legacy_presented`、`unavailable` 和 `unfinished`，同时列出最终与过程结果 ID；原 `results` 仍保留全部查询供核对。页面将过程结果折叠并标为未作为结论导出。

导出格式 `crm-agent-export-v2` 仅纳入最终采用的保存结果。已完成的历史回答缺少清单时，只认可表格/图表的明确 `result_id`；旧自动来源列表不作为结果选择证据。历史纯文字回答仅导出正文并注明引用缺失。未完成任务仅导出已有正文并注明尚未最终确认，不将临时展示或已纠正的探索结果当作结论。原始过程结果仍可在所属会话核对，业务数据库不会重查或改写。

发送给模型的明细预览与持久化导出结果分别管理。物化容量上限为十万行、50MB；超出后保存明确的截断/覆盖说明，不能宣称全量导出。页面按保存结果分页，不需重新读取业务库。查询总数始终是完整匹配数，不以物化容量冒充总数。

`RenderXLSX(ExportDocument)` 和 `RenderHTML(ExportDocument)` 不接收数据库连接，只渲染已保存结果。导出入口需要验证会话归属后构建文档，下载再次验证。缓存保留七天；缓存过期可由保存结果再生成，无需读取当前业务库。

Excel 包含“口径说明”“回答内容”及最终采用结果的工作表。说明页含运行、模型、公共规则版本、时点、查询、总行数/导出行数、截断、覆盖、来源、引用状态和未导出的过程查询数量；所有用户文字通过 `SetCellStr` 写入，`=`、`+`、`@` 及制表符前缀均不会变成公式。超过 Excel 文本或行列限制明确报错，不静默截断；超过十五位的整数作为文本保留精度。

HTML 报告使用转义模板，无远程资源、脚本或模型原始 HTML。图表仅由保存结果中的有限数值生成 SVG；支持柱状、折线、饼图、散点。图表沿用原回答中的持久化预览（最多五百行），表格和 Excel 导出全部已物化行，范围不同明确标注。未知图表类型、不可用列、非数值/非有限值拒绝。表格包含完整性说明，浏览器打印可生成 PDF。

## 数据口径与规则维护

数据字典见 `Agent-Data-Dictionary.md`。首跟、负责人、发生日期、当前回访、净成交与实际现金收入必须分别说明。缺失字段和证据不足标为缺口，不能回填零或猜测历史值。

个人偏好只有明确保存后生效，主要影响表达和默认分析习惯。公共业务规则需管理员发布版本，运行保存版本快照；旧运行和导出不随公共规则后续修改而改变。用户偏好和跟进文字都不能覆盖系统安全、权限或事实规则。

修改模型、价格、数据字典、脱敏策略或公共口径时重跑相关独立预期测试，并执行关键真实模型问题三次。可控模型的工具返回、SSE 与异常测试不能证明自然语言分析正确。

## 资源调度

逻辑上最多两项分析并发；快照准备使用单独的一项资源槽，完成准备后立即释放，两项模型调用与快照查询仍可并行。此限制针对完整HTTP性能回归发现的竞争，不改变用户问题或数据范围。等待资源、停止、权限失效与180秒超时使用同一运行上下文。

预算费用按配置的版本化标准单价和供应商返回Token用量核算；缓存或活动优惠未自动扣减，需与供应商账单核对。未知用量保留预留。

## 第二阶段：固定指标模式（2026-10-14 起默认）

生产默认 `FixedMetrics`：模型只选择服务端固定指标并写不含数字的解读，表格/图表/导出由服务端渲染；
设计与指标清单见 `docs/Agent-Fixed-Metrics.md`，验收题见 `docs/Agent-Metrics-Cases.json`
（`scripts/agent_metrics_evaluate.py`）。仅在设置 `KXONE_AGENT_FREE_ANALYSIS=1` 时恢复自由分析。
常用指标可在 AI 开关关闭时手动运行，不调用模型、不占模型额度。
